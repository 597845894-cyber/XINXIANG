## Context

当前项目只有 OpenSpec 规划，没有既有应用代码或数据需要兼容。设计需满足四项规格，并以 Windows 10/11、8 GB 内存、CPU-only 为最低基线；通知内容的采集、OCR、理解、存储、搜索、提醒和备份均在本机完成。参见 `proposal.md` 的动机与范围，以及四个能力规格中的可观察行为。

主要约束是本地中文理解质量、有限内存、Windows 后台提醒、静态数据加密和以后迁移到移动端时的数据可移植性。首版允许联网获取不含用户数据的应用或模型更新，但核心功能安装完成后不得依赖网络。

## Goals / Non-Goals

**Goals:**

- 建立低内存、可打包的 Windows 桌面架构，使 UI、分析任务和提醒互不阻塞。
- 用确定性解析与本地小模型组合生成结构化候选，并让所有高风险不确定性进入人工确认。
- 让原始通知、分析版本、候选任务和用户确认任务彼此分离，支持追溯、重新分析和通知更新。
- 通过数据库与附件加密、内容安全日志和无内容出站边界兑现本地隐私承诺。
- 使用版本化数据格式和加密备份，为以后原生移动端迁移保留路径。

**Non-Goals:**

- 不追求无人工确认的全自动任务创建。
- 不在首版训练自有模型，也不针对所有校园方言和通知模板达到完全识别。
- 不实现账号、远程服务、跨设备同步、微信自动采集或微信小程序运行时。
- 不保证应用进程被用户彻底退出时仍能准时弹出提醒；下次启动时采用补发机制。

## Decisions

### 1. 使用 Tauri 2 桌面壳、React/TypeScript 界面和 Rust 本地核心

界面负责收件箱、导入、核对和任务视图；Rust 核心负责数据访问、加密、任务队列、日期解析、模型调用和 Windows 集成。两者仅通过显式、类型化的本地命令交换结构化数据，原始文件路径不直接暴露给界面。

选择 Tauri 而不是 Electron，是为了减少常驻内存和安装体积，把更多 8 GB 设备资源留给 OCR 与本地模型。选择 Rust 核心而不是在前端执行分析，是为了统一管理原生推理库、数据库事务、DPAPI 密钥和后台任务。相比 Windows 专属的 .NET/WinUI，此方案增加了原生依赖打包复杂度，但 Web UI 和核心数据合同更容易复用于未来的 Tauri 移动端或其他原生外壳。

```text
┌─────────────────────────────────────────────────────┐
│ React UI：收件箱 / 快速导入 / 核对 / 任务 / 设置   │
└──────────────────────┬──────────────────────────────┘
                       │ typed local commands/events
┌──────────────────────▼──────────────────────────────┐
│ Rust application core                              │
│ capture │ analysis queue │ task service │ reminders │
├─────────┴───────────────┬┴──────────────┴───────────┤
│ encrypted data store    │ local inference adapters  │
└─────────────────────────┴───────────────────────────┘
```

### 2. 采用“规则快路径 + 本地模型 + 确定性校验”的分析流水线

图片先通过本地 ONNX OCR 适配器产生文字块、坐标和置信度。文字规范化后，日期、时间、网址、手机号和显式地点等字段先由规则解析；只有需要语义理解、分类或多任务拆分的部分交给本地量化中文指令模型。模型必须以受约束的结构化格式输出，随后由校验器验证字段类型、证据位置、时间关系和冲突。

分析流水线为：

```text
原始输入 → OCR → 文本规范化 → 规则提取 → 本地语义模型
                                      ↓
分析版本 ← 证据绑定 ← 冲突/缺失/时间校验 ← 结构化输出
```

选择分层方案而不是只使用正则，是因为长通知、多阶段任务和变更语义无法稳定由规则覆盖；不选择纯大模型方案，是因为它在 CPU-only 设备上更慢，也更容易编造缺失字段。OCR 和语义模型都放在适配器后，最终型号由固定校园通知样本集上的准确率、峰值内存、包体和耗时基准决定。首版目标是典型千字以内文字在 8 秒内、单张清晰聊天截图在 15 秒内形成可核对结果；超时任务可取消且不阻塞界面。

### 3. 将原始通知、分析版本和正式任务分层持久化

核心实体及关系如下：

- `Notice`: 导入类型、不可变原始内容引用、导入时间、可编辑的通知发布时间和收件箱状态。
- `SourceAsset`: 加密图片、内容类型、尺寸、加密校验值；业务层不保存明文临时副本。
- `AnalysisRevision`: OCR 文字、模型与规则版本、类别、候选字段、可信状态和证据位置。重新分析只新增版本。
- `TaskCandidate`: 某个分析版本提出的动作，可确认、编辑、忽略、合并或拆分。
- `Task` 与 `TaskRevision`: 用户确认后的稳定任务及其修改历史；“已过期”按时间派生，完成与取消为持久状态。
- `Reminder`: 任务的本地触发时间、触发/取消状态和幂等标识。
- `NoticeRelation`: 重复、补充、改期或取消的候选关系及用户确认状态。

该分层避免重新分析覆盖用户决定，也允许每个任务字段回溯到分析证据或用户修改。所有跨实体写入使用数据库事务；耗时分析先写版本草稿，完整校验后再原子切换为可核对版本。

### 4. 通知发布时间是相对日期解析的显式输入

日期解析服务接收原始表达、通知发布时间和本地时区，输出绝对时间或时间范围、精度、原始表达及歧义原因。导入时间只能作为待确认的回退值。通知发布时间改变时，只重算依赖相对表达的候选字段，并生成差异；已经确认的正式任务不被静默改写。

第四阶段在完整 OCR 之前提供轻量候选路径：导入截图时仅扫描 PNG/JPEG/WebP 的内嵌文本元数据和可读时间串（例如 EXIF `DateTimeOriginal` 或 `YYYY-MM-DD HH:MM`），生成低风险的候选发布时间并标注来源；无法提取时继续使用导入时间暂定值。该路径不宣称能识别聊天气泡中的全部文字，画面 OCR、坐标和置信度仍属于第五阶段。

这比直接以当前时间解析更复杂，但能正确处理用户晚几天导入截图的常见场景。

### 5. 使用 SQLCipher、附件认证加密和 Windows DPAPI 保护本地数据

结构化数据保存到 SQLCipher 数据库；原始截图与大型附件使用独立随机数据密钥进行 AES-256-GCM 加密。应用主密钥由 Windows DPAPI 绑定当前用户保护，数据库中只保存密文引用、随机数和认证信息。分析工作目录只允许短期受控明文缓冲，任务结束或异常恢复时清理。

备份不复用 DPAPI 密钥，而是使用用户备份口令经 Argon2id 派生独立密钥，将版本清单、数据库导出和附件重新封装为认证加密容器。恢复先在隔离临时目录验证版本、认证标签和清单，再通过事务替换或导入，失败时不修改现有数据。

相比只依赖 Windows 文件权限，这能保护被复制的数据目录；代价是 DPAPI 配置损坏后只能依靠用户备份恢复，因此首次积累数据后需要提示创建备份。

### 6. 从架构上隔离联网能力

业务核心和分析进程不提供通用 HTTP 客户端，界面内容安全策略禁止加载远程脚本、字体和图片。可选的应用/模型更新器作为单独边界，仅接收版本、平台和组件版本，不可访问数据库密钥、数据库连接、附件目录或通知对象。日志 API 只接受枚举错误码、耗时区间和组件版本，不接受任意正文。

测试中使用本地代理或网络审计验证导入、分析、搜索、提醒和备份流程没有内容出站。与依靠团队约定相比，这一边界更难被后续依赖或遥测意外破坏。

### 7. 使用持久提醒调度器和系统托盘生命周期

应用关闭主窗口时默认驻留系统托盘。调度器从数据库加载下一批提醒，以稳定幂等标识写入应用内通知中心并触发 Windows 本地通知。启动或系统唤醒后扫描错过的提醒，按任务合并补发；完成或取消任务时在同一事务中取消未来提醒。

首版不安装独立 Windows 服务。这样权限与安装复杂度较低，但用户明确选择“彻底退出”后无法准时触发提醒，界面需要清楚区分“关闭窗口”和“退出应用”。

### 8. 更新识别只产生建议，不直接修改任务

新通知先通过规范化内容哈希检测完全重复，再结合局部文本相似度、关键实体、时间和已有任务标题生成本地关联候选。对于改期或取消，系统创建包含新旧值及双方证据的变更建议；只有用户确认后才写入新的任务修订并重排提醒。

不使用自动覆盖，因为错配通知造成的漏交风险高于多一次人工确认的成本。

### 9. 以版本化合同保留移动端迁移能力

数据库迁移、备份清单、分析输出和领域命令均带版本号。UI 不依赖 Windows 文件系统路径或 OCR 实现细节。未来原生手机 App 可复用领域格式和部分前端，但移动端模型、提醒与存储适配器需要单独实现。

严格“任何数据不离开设备”与云同步冲突，因此本设计只提供本地加密导入导出。未来若隐私原则调整为“明文不离开设备”，应另建变更设计端到端加密同步，不能在本变更中预留隐藏上传路径。

## Risks / Trade-offs

- [本地小模型在复杂通知上准确率不足] → 建立脱敏合成与公开通知评测集，分字段衡量准确率；所有正式任务经过确认，低可信字段强制聚焦。
- [CPU-only 推理过慢或峰值内存超过 8 GB 基线] → 规则快路径、模型懒加载、单任务队列、量化模型和可取消分析；模型选择必须通过目标设备基准。
- [OCR 对长截图、小字或复杂聊天背景表现不稳] → 图像预处理、分块识别、低可信区域标注和手工修正入口，原图始终可见。
- [密钥或数据库损坏导致本地数据不可恢复] → 原子写入、数据库完整性检查、版本化迁移、加密备份提示和恢复前验证。
- [静态加密增加搜索和附件预览复杂度] → 数据在授权进程内短时解密，搜索索引保存在加密数据库中，不创建持久明文缓存。
- [用户彻底退出应用后错过提醒] → 托盘默认常驻、退出前提示影响、下次启动合并补发；首版不引入高权限后台服务。
- [更新/取消通知匹配错误] → 仅提出候选、展示双方依据、用户确认后修改，并保留任务修订历史。
- [Tauri 原生推理依赖在 Windows 打包复杂] → 先完成最小打包验证和用户在当前 Windows 主机的人工安装测试，再扩展完整 UI；所有推理库锁定版本与校验值。

## Migration Plan

1. 先交付不含用户数据的桌面壳、加密空数据库和模型资源检查，验证 Windows 10/11 安装、启动、卸载与离线运行。
2. 通过版本化数据库迁移逐步加入通知、分析、任务、提醒和关系表；每次迁移前创建本地恢复点，失败时保持旧版本可读。
3. 模型作为受校验的本地资源包随安装包提供或由用户显式安装；升级时保留旧模型，直到新模型通过加载与最小推理检查。
4. 首版没有既有生产数据迁移。后续版本升级必须先验证数据库和附件，再提交迁移；失败时回滚程序与数据库恢复点，不回滚用户单独创建的加密备份。
5. 卸载默认保留加密用户数据并明确询问；只有用户选择删除数据时才移除数据库、密钥包装和附件。

## Open Questions

- 最终 OCR 模型与 1.5B 至 3B 量化中文模型的组合，需要在目标设备和校园通知评测集上基准后确定，不改变分析适配器和规格。
- 安装包采用 MSIX 还是签名安装程序，需要结合模型包大小、自动更新方式和学校环境的安装权限测试后确定。
