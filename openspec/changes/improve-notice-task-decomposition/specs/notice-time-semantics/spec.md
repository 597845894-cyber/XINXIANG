## Purpose

为校园通知中的中文绝对日期、相对日期、时段和截止表达建立一致的本地时间语义，避免“下午上课前”等表达被错误解析、跨日显示或被模型静默猜测。

## ADDED Requirements

### Requirement: 解析中文截止时间表达
系统 MUST 支持包含年月日、月日、星期、相对日期、时段和“前/之前/前完成”等常见中文截止表达，并输出结构化的本地日期时间或明确的待确认状态。

#### Scenario: 月日加时段和事件边界
- **WHEN** 通知写明“8月31日下午上课前提交”
- **THEN** 系统将截止日期识别为当年8月31日，并保留“下午”和“上课前”的语义边界；若无法知道具体上课时间，则时间字段标记为待确认而不是填入任意分钟

#### Scenario: 相对星期表达
- **WHEN** 通知写明“本周五16:00前完成”
- **THEN** 系统根据通知接收时间所在周计算日期，生成本地时区的16:00截止时间，并在结果中保留来源表达

### Requirement: 时间作用域正确继承
当一个共享截止时间约束后续多个动作时，系统 MUST 将该时间作用域应用于所有相关候选，除非某个动作有更具体的时间；不相关的背景句或条件说明不得继承该截止时间。

#### Scenario: 共享截止时间
- **WHEN** 通知先说明“8月31日下午上课前需要提交以下纸质材料”，随后列出两项材料及其准备要求
- **THEN** “提交纸质材料”及其直接准备步骤继承该截止时间，并在候选中标注为共享来源

#### Scenario: 更具体时间优先
- **WHEN** 通知共享截止时间为8月31日，但其中一个动作另写明“8月30日前完成盖章”
- **THEN** 盖章动作使用8月30日作为截止时间，其余相关动作继续使用共享截止时间

### Requirement: 时区和歧义处理
系统 MUST 以用户设备本地时区保存和展示通知时间，不得因序列化为 UTC 导致日期跨日；无法从上下文可靠确定年份、具体时刻或“下午”的边界时 MUST 标记待确认并展示原文。

#### Scenario: 本地日期不跨日
- **WHEN** 用户设备位于中国时区且通知截止时间为8月31日23:59
- **THEN** 保存和展示的日期均为8月31日，不得显示为9月1日

#### Scenario: 模糊时段待确认
- **WHEN** 通知只写“下午完成”且没有可推导的事件时间
- **THEN** 系统保留日期或时段信息，将具体时间标记为待确认，不得擅自设为12:00或18:00
