## Why

真实校园通知中的任务通常同时包含总任务、准备步骤、条件分支和共享截止时间。当前分析结果对这类通知拆分不准确：会遗漏编号材料、把说明句误判为任务、丢失“无评语时联系老师”等条件动作，并可能把“8月31日下午上课前”解析成错误日期或时区。需要把任务拆分从简单的候选列表升级为可验证的动作结构，先解决文字通知的核心价值，再进入后续模型优化。

## What Changes

- 统一生产环境与评测环境使用的千问 system prompt、输出 JSON Schema 和版本标识，禁止模型用自由文本替代结构化结果。
- 按“可执行动作”拆分通知：完整覆盖编号列表、并列要求、条件动作和材料准备步骤；纯背景、提醒、成绩影响说明不得单独生成任务。
- 增加任务之间的父子步骤/依赖关系，表达“提交纸质材料”与“导出手册、补评语、盖章、拍照插入、装入档案袋”等准备动作的关系，并允许用户分别确认。
- 增加共享时间作用域和中文时间语义解析，支持“8月31日下午上课前”“本周五16:00前”等表达；无法可靠确定的时间必须待确认，不得静默猜测。
- 扩展规则回退的动作词和证据绑定校验，要求每个候选都能回指原文片段，并阻止没有动作证据的候选进入确认列表。
- 增加真实通知回归样本和质量门槛，至少覆盖本次实习通知的 7 个预期动作、条件分支、共享截止时间和父子依赖。
- 保持通知数据本地处理、人工确认后创建正式任务、原文不可被分析结果覆盖等既有边界。

## Capabilities

### New Capabilities

- `notice-task-decomposition`: 将文字通知解析为动作级任务树/依赖图，覆盖编号任务、条件步骤、背景句过滤、证据绑定和人工确认。
- `notice-time-semantics`: 解析中文日期、时段、相对日期和“之前/之前完成”等截止语义，保留本地时区并对歧义值进行待确认标记。

### Modified Capabilities

无。项目当前没有已同步到 `openspec/specs/` 的主规格，本变更建立新的行为契约。

## Impact

- 影响本地 Qwen 分析适配器、提示词与 JSON 合同、候选任务数据模型、规则回退解析器、日期解析器、分析版本保存和任务确认界面。
- 需要为任务候选增加稳定的父任务/步骤标识、依赖类型、时间作用域和逐任务证据字段；现有扁平候选数据需要兼容读取或迁移。
- 新增领域评测与人工验收数据，不引入云端 API、联网推理或通知内容外传。
- 变更完成后应能对用户给出的实习通知稳定地产生可核对的动作集合，而不是直接自动创建未经确认的任务。
