## Context

现有实现已经有本地 Qwen 适配器、`StructuredModelOutputV1`、规则回退和扁平 `TaskCandidatePayloadV1`。生产提示词和评测提示词没有完全共享；模型合同最多允许 5 个任务，且候选没有父子关系或证据范围。日期解析集中在 `understanding.rs`，当前会把时间序列化为 `Z`，并将共享时间粗略套用到整条通知。详见 proposal.md 和两份能力规格。

## Goals / Non-Goals

**Goals:**

- 让模型、规则回退和评测使用同一套动作拆分定义与结构化合同。
- 用任务图表达汇总任务、准备步骤、前置依赖和条件动作，同时兼容读取旧的扁平候选。
- 将时间解析拆成“原文表达、作用域、解析状态、本地值”四个层次，阻止跨日和静默猜测。
- 对真实通知建立可重复的领域回归测试和人工核对入口。

**Non-Goals:**

- 不在本变更中重新引入截图/OCR、远程模型或自动确认正式任务。
- 不要求模型决定用户个人是否适用；无法判断的适用对象继续交由用户确认。
- 不在没有迁移证据的情况下删除历史分析或已确认任务。

## Decisions

### 1. 将结构化合同升级为任务图版本

新增 `analysisSchemaVersion=2` 和 `modelPromptVersion`，任务字段增加 `id`、`parentId`、`dependsOn`、`relation`（`standalone`、`parent`、`preparation`、`conditional`）、`condition`、`timeScopeId` 及逐项 `evidence`。保留 v1 读取器：旧候选加载时映射为 `standalone`，不自动推断依赖。生产和 `benchmarks/semantic` 共用同一份 schema/prompt 资源，启动时校验版本一致。

选择显式任务图而不是仅在标题中拼接“准备：”，因为 UI、确认逻辑和未来提醒都需要知道哪些步骤是前置关系；显式版本也能让历史分析可追溯。替代方案是继续平铺候选，但无法表达“提交材料”与其准备工作的关系。

### 2. 采用句段级动作抽取，再做依赖归并

先按标点、编号和连接词切分为句段，识别动作词、动作宾语、条件词和说明句。模型负责提出动作候选及证据，服务端执行三类确定性校验：证据必须是原文连续片段；候选标题必须包含动作语义；同一动作不得重复。随后根据“提交/上交/完成”等汇总动作和“导出/联系/盖章/拍照/插入/装入”等准备动作建立父子或前置关系。

规则回退只生成有动作证据的候选，动作词表与模型合同保持一致。相比直接依赖模型输出，这能防止背景句变成任务，也能在本地模型不可用时保留可解释的低可信结果。

### 3. 用共享时间作用域承载截止语义

日期解析器先抽取时间表达及其作用范围：标题/引导句后的列表项继承 `timeScopeId`，单项明确时间覆盖共享值。解析结果同时保存 `dueExpression`、`dueLocal`、`precision`（`date`、`period`、`exact`）和 `resolutionStatus`（`resolved`、`needsReview`、`conflict`）。所有持久化值使用带偏移的本地 ISO 时间或纯日期，禁止在业务层强制追加 `Z`。

“上课前”等事件边界若没有课程表数据，只保留日期与时段并标记待确认；“本周五”按通知发布时间所在周计算。替代方案是将所有时间归一为当天 23:59，但这会制造虚假精度并掩盖用户真正需要确认的边界。

### 4. 以领域评测作为发布门槛

新增真实通知回归样本（脱敏）和精确期望图。示例实习通知验收两个主要候选，导出、评语、盖章、拍照、插入和装袋作为详情证据；指标拆为聚合准确率、背景误报率、证据合规率和时间待确认率。

## Risks / Trade-offs

- [任务图字段增加迁移和 UI 复杂度] → 先在候选核对界面以树状/缩进列表展示，旧候选按独立任务显示，并保留 v1 反序列化。
- [1.5B 模型仍可能漏掉长通知动作] → 增加输入分段、动作召回规则和“未覆盖编号项”警告；不得用标题猜测补齐证据。
- [中文事件边界无法精确换算] → 保存原文表达和待确认状态，禁止伪造具体分钟。
- [多个时间表达可能冲突] → 按作用域检测冲突，冲突候选不可快速确认。
- [合同版本漂移] → 将 schema、prompt、Rust/TypeScript 校验和评测 fixture 放在同一版本检查中，CI 失败即阻止发布。

## Migration Plan

1. 先增加 v2 合同、版本检查和 v1 兼容读取，不改变现有正式任务数据。
2. 接入句段级拆分、动作词回退、证据校验和任务图持久化；旧分析结果保持只读。
3. 接入时间作用域与本地时区保存，针对历史候选只在重新分析时生成新版本。
4. 更新核对界面和确认命令，确保父任务与子步骤可分别确认，确认记录引用候选 ID。
5. 运行领域评测和离线人工验收；若质量不达标，通过功能开关回退到 v1 规则候选，不覆盖原文或已确认任务。
