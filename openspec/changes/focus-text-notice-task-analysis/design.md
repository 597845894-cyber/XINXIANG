## Context

现有项目已有文字导入、规则解析、分析队列、候选任务和人工确认的骨架，但生产 OCR 和生产语义模型尚未接入。已选择的 Qwen2.5-1.5B GGUF 模型与 Windows CPU 运行时位于 E 盘的本地模型目录；模型文件不得进入 Git 或复制到 C 盘缓存。详见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 将首版入口收敛为纯文字通知，消除图片采集与 OCR 的运行时、资源和验收依赖。
- 通过受约束的本地千问推理提高分类、多个独立行动拆分和字段提取的覆盖率。
- 让模型不可用或输出异常时保持数据完整，并能回退到明确的人工处理路径。
- 在现有的分析版本和任务候选边界内实现，不改变“用户确认才创建正式任务”的规则。

**Non-Goals:**

- 不支持聊天截图、PDF、附件、剪贴板图片或任何 OCR。
- 不调用千问 API、云端模型、账号服务或联网许可服务。
- 不追求模型结果无需人工核对，也不自动改写已确认任务。

## Decisions

### 1. 将图片路径作为受控的首版范围移除

快速导入和桌面命令仅接受非空文字。UI 删除图片按钮、图片预览和 OCR 修正入口；后端对旧图片导入命令返回稳定的“不支持”错误，不读取输入内容。数据库中的历史图片记录不在本变更中迁移或删除，避免清理用户数据，但首版 UI 不再创建新的图片通知。

这比保留“实验性图片导入”更清晰，也比立刻删除所有图片存储结构风险更低。将来恢复截图能力须建立新的独立变更并重新引入完整隐私、性能和识别验收。

### 2. 以本地运行时调用量化 Qwen，并隔离进程边界

Rust 分析队列为每项文字分析启动受控的本地推理进程，传入固定版本的提示词和通知文本，读取单一 JSON 响应。运行时、模型路径和 SHA-256 校验由模型资源清单管理，默认使用用户配置的 E 盘本地资源根目录；资源缺失仅显示恢复步骤，绝不自动联网下载。

选择进程边界是为了让超时、取消和模型崩溃可被回收，也避免模型库与桌面进程争抢内存。替代方案是在 Rust 中直接链接推理库，但这会增加 Windows 编译和打包复杂度，且较难隔离异常。

### 3. 将模型输出收窄为可验证的 JSON 合同

提示词要求输出通知类别、变更意图和候选数组。每个候选只允许标题、可选字段、可信状态和原文证据片段/范围。接收端先执行 JSON schema、字段类型、证据回指、日期解析与冲突检查，再原子写入新的分析版本；任何检查失败都不保存候选。

规则解析保留为模型提示的已知事实和不可用时的低可信恢复方案，但不把规则推断伪装成模型确认结果。这比接受自由文本再由 UI 猜测更容易测试，也能防止无依据字段进入任务表。

### 4. 使用合成文字通知建立拆分质量门槛

评测集只保留文字样本，覆盖单任务、多阶段、多任务、相对日期、缺失字段、冲突、改期、取消和仅供知晓。发布前记录分类、任务数量、字段、证据绑定、结构化合规率和耗时；高风险错误必须进入待确认，而不是静默产生正式任务。

## Risks / Trade-offs

- [1.5B CPU 推理响应较慢] → 单并发、可取消、限制输入长度和输出 token，并记录文字样本耗时。
- [模型虚构字段或遗漏任务] → 强制证据回指、字段校验、低可信标记和用户确认门槛。
- [本地模型路径被移动或损坏] → 启动前校验清单与 SHA-256，显示本地恢复入口，不访问网络。
- [旧图片代码与数据遗留扩大维护面] → 先停止入口和分析路径，待文字版验收后在单独变更中决定安全清理或兼容策略。
- [本地运行时进程异常] → 超时后终止子进程，保留原文并不写入半成品。

## Migration Plan

1. 添加文本首版功能开关并移除图片/OCR 的用户入口；旧图片通知保持只读，不自动删除。
2. 配置 E 盘本地模型资源根目录，完成运行时、模型和校验清单的健康检查。
3. 接入受约束推理与字段验证，先在合成文字评测集运行。
4. 将通过的文字分析流程与人工核对打包为试用版本；发现结果问题时可关闭模型路径并回退到现有规则候选，不影响已确认任务。
5. 在用户确认文本首版稳定后，另行决定是否删除图片数据结构和依赖。
