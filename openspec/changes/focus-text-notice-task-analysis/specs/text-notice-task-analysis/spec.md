## Purpose

在不上传通知内容的前提下，使用用户设备上的千问模型把一条文字通知拆分为可核对的多个任务候选，并明确暴露依据与不确定性。

## ADDED Requirements

### Requirement: 本地千问文字分析
系统 SHALL 使用已安装在用户设备上的本地千问模型分析文字通知，且通知原文、提示词、模型输出和派生字段 MUST 不发送到远程服务。

#### Scenario: 本地模型可用
- **WHEN** 用户分析一条文字通知且本地模型资源通过完整性与启动检查
- **THEN** 系统在本机完成分类、字段提取、任务拆分和变更意图分析

#### Scenario: 模型资源不可用
- **WHEN** 本地模型、运行时或资源校验值缺失或损坏
- **THEN** 系统不发起远程下载或推理，并说明需要恢复本地模型资源的原因

### Requirement: 受约束的候选任务输出
系统 MUST 将模型结果校验为结构化通知类别、零个或多个任务候选及变更意图；每个候选 MUST 包含任务标题、可为空的时间/地点/材料/适用对象/是否必须字段、可信状态和原文证据。

#### Scenario: 通知包含多个独立行动
- **WHEN** 一条通知要求报名、提交材料并参加后续活动
- **THEN** 系统生成三个可独立编辑和确认的任务候选，并分别展示其原文依据

#### Scenario: 通知字段缺失或无依据
- **WHEN** 原文没有明确给出候选任务的时间、地点、材料或适用对象
- **THEN** 系统将对应字段保持为空或标记待确认，不得将模型猜测作为确定值

### Requirement: 不可靠模型输出可恢复
系统 MUST 验证模型输出的格式、字段类型、证据范围和时间合理性；无效输出、超时、取消或模型进程异常 MUST 不生成半成品候选或正式任务，并提供重试、规则回退或人工创建任务的恢复入口。

#### Scenario: 模型输出无效
- **WHEN** 模型输出无法解析为符合约束的结构化结果
- **THEN** 系统保留原始通知、记录不含通知内容的错误类别，并提示用户选择恢复方式

#### Scenario: 分析被取消
- **WHEN** 用户取消正在进行的分析
- **THEN** 系统终止本地推理且不保存半成品分析版本或候选任务

### Requirement: 自动候选必须经过人工确认
系统 MUST 在模型生成候选后集中显示低可信、冲突或缺失字段；候选任务在用户确认前不得成为正式任务或修改已有任务。

#### Scenario: 高风险字段待确认
- **WHEN** 候选的截止时间、适用对象或是否必须存在低可信、冲突或缺失
- **THEN** 系统将该字段置于核对焦点，并阻止无提示的快速确认

#### Scenario: 用户确认拆分结果
- **WHEN** 用户逐项核对并确认多个候选任务
- **THEN** 系统仅为已确认的候选创建正式任务并保留分析版本与原文依据
