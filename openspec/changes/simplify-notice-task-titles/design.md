## Context

当前本地千问分析器、规则回退和前端候选页面把准备动作平铺为任务，导致标题过细；任务表默认时间筛选又可能隐藏刚确认的任务；候选卡片横向压缩造成中文竖排。实现必须保持纯本地文字处理、兼容历史候选，并且不重新引入截图识别或远程服务。

## Goals / Non-Goals

**Goals:**

- 以“主要内容 + 时间概括”生成少量可直接使用的任务标题。
- 让模型输出、规则回退和结构化校验共享同一聚合规则，并保留原文证据与详情。
- 让确认后的任务在全部任务和适合的时间视图中可见，统计与列表一致。
- 让分析卡片在窄窗口下保持多行可读布局，并覆盖长中文标题。

**Non-Goals:**

- 不恢复截图/OCR，不接入联网模型或云端同步。
- 不自动确认候选，不改变历史正式任务的内容或状态。
- 不把材料准备步骤强制隐藏；用户仍可在核对时主动拆分为独立任务。

## Decisions

### 1. 先聚合再展示，保留可逆细节

在结构化结果归一化阶段按截止语义、提交对象和完成目标计算聚合键；同键动作合并为一个主要候选，动作列表、材料、条件和证据写入详情字段。候选保留稳定 ID，使用户拆分时可追溯。相比仅修改显示标题，这能避免任务表仍被过细候选污染；相比删除细节，这保留了核对所需信息。

### 2. 共享确定性聚合规则与回退路径

更新本地千问 system prompt、规则回退和服务端校验，使三者都遵循“不同平台/入口、截止时间、提交对象或独立确认目标才拆分”。服务端以连续证据和动作语义做最终校验；模型输出不符合规则时进入待确认或规则回退，不静默补造标题。同一目标下的导出、联系、盖章、拍照、插入和装袋只进入详情；实习通知的回归基线固定为两项。

### 3. 统一任务表查询状态

抽取单一的任务筛选谓词，同时驱动卡片列表、侧栏计数和空状态；“全部任务”包含待办和已完成任务，排除已取消任务，确认成功后刷新任务查询并在必要时提示用户切换视图。这样不会因默认“本周”筛选或缺少截止时间而误认为任务未创建。

### 4. 用响应式多行候选卡片替代横向挤压

候选卡片采用纵向分区或可换行网格，标题、时间、状态和证据列设置 `min-width: 0`、自然换行和合理的最小宽度；窄窗口时允许字段堆叠。保留现有颜色和交互语义，仅调整布局与可读性。

### 5. 用脱敏样本设定聚合门槛

将实习通知 fixture 的期望固定为两项主要候选，并验证第二项详情仍覆盖所有材料/条件证据；补充不同截止时间、不同提交对象和无日期样本，防止过度合并。

### 6. 与既有拆分变更的衔接

`improve-notice-task-decomposition` 中的 8 动作验收标准必须在本变更实施前更新或标记为被本变更取代。代码、fixture 和评测只保留一套生效的任务数量标准，历史分析数据仍按兼容读取规则展示。

### 7. 明确本地回退开关

新增本地配置 `task_summary_mode`，取值为 `aggregated` 或 `flat_legacy`，默认值为 `aggregated`。回退只影响重新分析时的候选生成，不重写通知、历史分析版本或正式任务；切换状态保存在设备本地，不通过网络同步。

## Risks / Trade-offs

- [聚合过度可能漏掉用户想单独跟踪的步骤] → 保留详情和主动拆分入口，并对不确定独立性标记待确认。
- [标题仍可能过长] → 默认标题限制为 32 个中文字符，超出部分放入详情，不截断时间概括。
- [旧候选缺少聚合字段] → 兼容读取为独立候选，重新分析才应用新聚合逻辑。
- [“全部任务”包含已完成任务导致数量变大] → 明确区分未取消总数与当前状态筛选统计，并在界面标注状态。

## Migration Plan

1. 先协调并更新 `improve-notice-task-decomposition` 中相互冲突的 8 动作 fixture/测试，再更新合同类型、提示词和本变更 fixture，加入聚合元数据并保留旧字段读取。
2. 接入服务端聚合、证据校验和待确认标记，新增单元与语义回归测试。
3. 更新候选卡片和任务表查询/统计，验证确认后刷新及空状态入口。
4. 在本地 Windows 离线环境运行回归和人工验收；若质量不达标，将本地 `task_summary_mode` 切换为 `flat_legacy`，不迁移或覆盖既有任务。

## Open Questions

无。32 个中文字符的标题上限、两项实习通知基线和回退开关默认值均已确定，可直接进入实施。
