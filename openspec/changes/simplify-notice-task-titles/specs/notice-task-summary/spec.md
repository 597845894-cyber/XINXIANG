## Purpose

让文字通知先提炼出少量可识别的主要任务标题与时间概括，再把材料、条件和原文依据保留在详情中，帮助学生快速建立可执行且不过度细化的个人任务表。

## ADDED Requirements

### Requirement: 聚合主要任务标题
系统 MUST 将同一通知中、同一截止语义下、指向同一完成或提交目标的动作聚合为一个主要任务候选。候选标题 MUST 表达主要内容，并可附带简短的时间概括；材料准备、办理条件和操作步骤 MUST 保留在详情或依据中，不得默认单独生成任务。

#### Scenario: 聚合实习收尾通知
- **WHEN** 用户导入包含完成校友邦任务、提交纸质材料以及手册评语、盖章、拍照和装袋说明的实习通知
- **THEN** 系统必须生成且仅生成以下两项主要候选：“完成校友邦上的实习任务”和“提交实习纸质材料（8月31日下午上课前）”，并在第二项详情中保留所有材料与条件说明

#### Scenario: 保留原文依据
- **WHEN** 聚合候选包含多个原文动作或材料说明
- **THEN** 系统为候选保留一个或多个通知中的连续证据片段，用户可在详情中查看，不得用模型改写内容冒充证据

### Requirement: 仅按独立目标拆分
系统 MUST 仅在事项具有不同平台或入口、不同截止时间、不同提交对象，或明确需要独立确认的完成目标时拆分为多个主要候选。共享截止时间且指向同一提交对象的准备动作 MUST 使用同一时间作用域并聚合到主要候选；无法确认是否独立时 MUST 合并并标记待用户确认。

#### Scenario: 不同提交对象分别成项
- **WHEN** 通知分别要求在不同日期向两个不同对象提交两类材料
- **THEN** 系统生成两个主要候选，并分别绑定对应提交对象、截止时间和证据

#### Scenario: 准备步骤不单独成项
- **WHEN** 通知要求提交实习材料，并说明导出、盖章、拍照和装袋步骤
- **THEN** 系统不为这些步骤单独生成主要任务，除非用户在核对时主动拆分

#### Scenario: 不同平台入口必须拆分
- **WHEN** 同一通知分别要求在校友邦完成线上事项，并向教师提交纸质材料
- **THEN** 系统生成两个主要候选，即使两者共享同一截止时间

### Requirement: 标题可直接用于任务表
系统 MUST 输出长度适合任务表单行展示的标题，标题应优先包含主要动作或结果与时间概括；标题缺少可靠时间时不得猜测具体日期或时刻，并 MUST 将原始时间表达放入详情或待确认字段。
默认自动生成的标题 MUST 不超过 32 个中文字符（含时间概括）；超出部分 MUST 放入详情，不能删除截止时间语义。

#### Scenario: 模糊时间保持原文
- **WHEN** 通知仅写“上课前”且系统没有对应课程安排
- **THEN** 标题最多显示“上课前”等原文概括，详情标记时间待确认，不得生成虚构的具体分钟

### Requirement: 聚合结果可追溯且可人工修正
系统 MUST 对每个主要候选保留稳定标识、原文证据、聚合说明和待确认原因，并允许用户在确认前编辑标题、拆分或合并候选。

#### Scenario: 用户主动拆分
- **WHEN** 用户认为一个聚合候选包含两个需要独立跟踪的目标并执行拆分
- **THEN** 系统创建两个可分别编辑和确认的候选，继承相关原文证据与时间作用域

#### Scenario: 证据不足
- **WHEN** 聚合候选无法绑定连续原文证据
- **THEN** 系统将其标记为待确认并阻止无提示快速确认，提供编辑、删除或人工创建入口
