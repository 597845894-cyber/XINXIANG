# Windows 安装包决策

## 首版选择

首版采用 Tauri 直接支持的 NSIS 安装程序，正式发布前对安装程序进行代码签名。当前阶段生成的开发安装包未签名，仅用于工程和用户在当前 Windows 主机的人工验收，不应分发给最终用户。

## 取舍

| 方案      | 优点                                                                          | 限制                                                                            | 首版结论 |
| --------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | -------- |
| 签名 NSIS | Tauri 原生支持；可携带较大的本地模型资源；适合普通 Windows 10/11 桌面安装流程 | 需要购买并维护代码签名证书；升级与卸载策略由应用维护                            | 采用     |
| MSIX      | 安装隔离、卸载一致、企业分发能力较好                                          | Tauri 不直接产出 MSIX；模型资源、签名、更新通道和学校设备策略需要额外工具链验证 | 暂不采用 |

若后续学校设备要求 Microsoft Store、Intune 或严格的应用容器分发，应另建 OpenSpec 变更重新评估 MSIX，不在首版隐藏引入第二套安装机制。
